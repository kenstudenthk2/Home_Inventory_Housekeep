# Home Inventory 系統 — 設計文件 (v1)

日期:2026-08-28
狀態:已批准 (approved)

## 背景同目標

一個個人/單一空間用嘅家居物品管理系統。用戶可以新增房間,喺房間入面加傢俬,喺傢俬入面記錄物品(數量、分類、可選到期日)。自訂嘅傢俬類型同分類會變成全局共用庫,喺其他地方嘅選擇器度可以搵返出嚟並重用。仲有一個全部物品嘅總覽頁,支援搜尋同篩選。

## 範圍 (Scope)

**v1 包含:**
- 房間管理(新增/編輯,含房間尺寸)
- 按房間類型建議預設傢俬,亦可自訂新增傢俬
- 傢俬底下嘅 item 管理(名稱、分類、數量、可選到期日)
- 全局共用庫:自訂傢俬類型/分類喺任何地方嘅選擇器都可搵到並重用
- 傢俬類型 icon(用現成 icon 集)
- 全局搜尋(揾物品擺喺邊個房間/傢俬)+ 選擇器內搜尋
- 全部物品總覽頁(篩選/排序)
- 首頁「快到期/已過期」提醒列表

**v1 明確不包含(留返第二階段):**
- 用戶登入/帳號系統(v1 唔需要登入,單一共用空間)
- AI 建議功能(用 LLM 分析成個 inventory,建議物品應該點樣重新擺放/搬去邊個房間更好)—— 呢個會係獨立嘅第二階段項目,有自己嘅 spec + plan
- 上傳自訂圖片/相做傢俬圖示(v1 只用現成 icon 集)
- 多用戶/同屋共用帳號

## 技術棧

- **前端 + API**:Next.js(App Router)+ TypeScript
- **資料庫**:Supabase(Postgres)
- **部署**:Vercel(應用)+ Supabase Cloud(資料庫)
- **UI**:Tailwind CSS

選用理由:呢個系統嘅資料結構(房間 → 傢俬 → item,加埋兩個全局共用庫)關聯性強,好適合關聯式資料庫表達 foreign key 關係。Next.js + Supabase 係一個成熟、少自砌零件嘅組合,亦都為將來加返登入功能留低擴充空間(Supabase 內建 Auth)。

## 資料模型

**核心表:**

| 表 | 主要欄位 | 說明 |
|---|---|---|
| `rooms` | `id`、`name`、`room_type`、`width_cm`(選填)、`length_cm`(選填) | 房間;尺寸留返第二階段 AI 建議功能用 |
| `furniture_types` | `id`、`name`、`icon_key` | 全局共用嘅傢俬類型庫 |
| `room_type_default_furniture` | `room_type`、`furniture_type_id` | 決定新增某類型房間時建議邊啲傢俬 |
| `furniture` | `id`、`room_id`、`furniture_type_id`、`custom_name`(選填) | 實際擺喺某房間入面嘅傢俬 instance |
| `categories` | `id`、`name` | 全局共用嘅 item 分類庫 |
| `items` | `id`、`furniture_id`、`category_id`、`name`、`quantity`、`expiry_date`(選填) | 擺喺某件傢俬入面嘅物品 |

**關係:**
```
Room (1) ──< Furniture (N) ──< Item (N)
              │                  │
    furniture_type (共用庫)   category (共用庫)
```

**全局共用庫運作方式:** `furniture_types` 同 `categories` 獨立於 room/furniture/item 之外存在。用戶喺任何選擇器輸入一個未存在嘅名稱,系統會插入呢個共用庫;之後喺任何地方嘅下拉/搜尋選擇器都會揾到呢個新選項。撞名(重複名稱)嘅情況會自動復用現有記錄,唔會建立重複項。

## 主要畫面/流程

| 畫面 | 內容 |
|---|---|
| 首頁 (Dashboard) | 房間列表(卡片式,顯示傢俬/物品數量)+「快到期/已過期」提醒列表 |
| 新增/編輯房間 | 名稱、房間類型、尺寸(xx cm × xx cm,選填)→ 按類型建議傢俬清單(checkbox + 自訂新增) |
| 房間詳情頁 | 顯示呢間房嘅所有傢俬(icon + 名稱),每件顯示 item 數量 |
| 傢俬詳情頁 | 顯示呢件傢俬入面嘅 item 清單(名稱、分類、數量、到期日),可新增/編輯/刪除 |
| 傢俬/Item 選擇器 | 下拉 + 可搜尋輸入框,揀現有選項或打新名稱自訂新增(自動寫入共用庫) |
| 全部物品總覽頁 | 表格/列表顯示全屋所有 item,可按房間、傢俬、分類、到期狀態篩選、排序;亦係全局搜尋嘅結果頁 |

**全局搜尋:** header 常駐搜尋列,輸入後導去全部物品總覽頁並即時篩選,結果顯示每件 item 所屬房間 + 傢俬。

## 驗證規則

- 房間名稱、傢俬名稱、item 名稱:必填,不可空白
- 房間尺寸(`width_cm`/`length_cm`):選填;填寫時必須為正數
- 到期日:選填;必須係合法日期
- 數量:必填,正整數,預設值 1

## 錯誤處理

- 資料庫操作失敗 → UI 顯示 toast/inline error,唔會令頁面 crash
- 共用庫撞名 → 自動復用現有記錄,唔建立重複項

## 測試計劃

- 資料庫 layer(CRUD 邏輯)嘅 unit test
- 全局共用庫嘅去重/搜尋邏輯 unit test(最易出 bug 嘅部份)
- 手動 QA 核心流程:新增房間 → 加傢俬 → 加 item → 全部物品總覽頁篩選/搜尋

## 第二階段(獨立項目,唔喺呢份 spec 範圍內)

- **AI 擺放建議**:用 LLM(例如 Claude API)分析成個 inventory(房間尺寸、傢俬、item 數量),建議物品應該搬去邊度擺放更好。需要獨立嘅 spec + plan,包括 API 用量/成本、prompt 設計、點樣將建議結果呈現喺 UI。
- 登入/帳號系統
- 自訂圖片做傢俬圖示
